# 문서 분류 엔진 2단계: Gemini 쪽 단위 판정 (그림자 모드) — 2026-11-21

`doc_ai.py` 는 PDF 쪽별 글자(개인정보 가림)를 Gemini 에 한 번 보내 "어느 쪽부터 어느 쪽까지 무슨 문서인지"를 받는다.
지금은 **그림자 모드**: 규칙(`doc_registry`) 결과대로 처리하고, AI 결과는 비교·기록만 한다. 앱 연결(app.py)은 아직 하지 않았다.

## 구성
| 파일 | 내용 |
|---|---|
| `doc_ai.py` | 종류 목록(CATALOG), 가림(mask), `classify_pages(raw)`, `agreement()`, `compare(raw)`, `shadow()` |
| `tests/test_doc_ai.py` | 가짜 Gemini 로 가림·스키마·구간 정리·비교·이미지 쪽·그림자 기록 (33개) |
| `scripts/compare_classifiers.py` | 폴더의 PDF 를 규칙 vs AI 로 비교해 표로 출력 (`--rules-only` 는 Gemini 호출 없음) |

## 종류 목록 (데이터, 코드 아님)
종류 하나 = `Kind(key, 이름, 설명, box, 예시 신호 1~3, media, part_of/section)` 한 줄. 프롬프트와 응답 enum 이 목록에서 만들어진다.
- 묶음(container): `mhr`(나의건강기록). 응답 종류로는 쓰지 않고, 구간 `mhr_checkup`·`mhr_visits`·`mhr_meds` 가 하나라도 있으면 문서 종류가 mhr 이 된다(`sections` 는 doc_registry 와 같은 키).
- PDF: nhis, prescription, checkup(단독 검진), policy, coverage, receipt, bill_detail — 규칙에서 꺼 둔(예약) 종류도 AI 는 판정한다.
- 이미지(이번 단계에서는 호출하지 않음): prescription(겸용), medical_payment, restaurant — screen_router 의 종류와 같다.
- 응답 enum = 그 media 의 종류 + `unknown`. 목록에 없는 답은 `unknown` 으로 바꾼다.

## 프롬프트·스키마
- 한 번 호출: `gemini.generate_json(model, [프롬프트, 쪽 글자], schema, temperature=0, feature="doc_ai", thinking="low")`.
  모델 `PICK3_DOC_AI_MODEL`(기본 gemini-3.5-flash), 생각 수준 `PICK3_DOC_AI_THINKING`(기본 low).
- 쪽 글자: 앞 30쪽, 쪽마다 가린 뒤 1,500자까지. 글자가 20자 미만인 쪽은 "글자 없음: 이미지 쪽"으로 표시(`needs_image`), 모든 쪽이 그러면 호출하지 않는다.
- 스키마: `{"segments": [{"type": enum, "page_from", "page_to", "start_hint", "confidence": 0~1, "evidence"}]}`.
- 정리(`clean_segments`): 쪽 범위를 1..보낸 쪽 수로 자르고, 순서대로 놓고, 붙어 있는 같은 종류는 합치고, 겹침은 **경계 한 쪽만** 허용(한 쪽에서 구간이 바뀌는 나의건강기록 때문), 그보다 많이 겹치면 뒤 구간을 줄이거나 버린다.
- 문서 종류: 묶음 구간이 있으면 그 묶음, 아니면 가장 많은 쪽을 차지한 종류(같으면 앞). 나머지는 `also`.

## 개인정보 가림 (`mask`)
| 대상 | 규칙 | 바꿈 |

| 전화 | `0X(X)-XXX(X)-XXXX`, `02)…`, `+82` | `[전화]` |
| 긴 숫자 | 숫자 10개 이상(사이 `-`·`*` 허용): 카드·계좌·하이픈 없는 휴대폰·발급번호 | `[번호]` |
| 메일 | `…@…` | `[메일]` |
| 주소 | `주소:` 뒤 줄 끝까지 | `[주소]` |
| 이름 | 성명·이름·환자(명)·수진자·피보험자·계약자·보호자·대상자·의사(명)·담당의·설계사(명) **뒤에 띄어 쓴** 한글 2~4자 | `[이름]` |

- 날짜(8자리)·쉼표 금액·약품 코드(9자리)·표 머리글은 남긴다(판정 신호).
- **한계**: 표시 없이 본문에 나오는 이름은 가리지 못한다. 진료 기관명·상병명·약품명 같은 건강 정보는 그대로 간다
  (종류 판정에 필요한 만큼만 보내려고 쪽당 1,500자로 자른다). 더 줄이려면 "쪽 머리 N줄 + 짧은 제목 줄"만 보내는 방식을 3단계에서 검토한다.
- 그림자 기록에는 evidence·start_hint 원문을 남기지 않는다(개인 글자가 섞일 수 있음).

## 비용
- 실측: 문서당 $0.0016~0.0039 (입력 1.7k~4.9k 토큰, 출력 70~220). 평균 약 $0.0027 ≈ 4원.
- 상한: 30쪽 × 1,500자 ≈ 입력 3만 토큰 → 약 $0.025(35원). 2027-01-01부터 3.6 Flash 가격이 두 배(gemini_prices.json 메모)라 그때 약 2배.
- 그림자 모드는 공유 PDF 마다 1회 추가 호출이므로 하루 한도(`bump_usage`) 안의 PDF 수 × 위 금액.

## 그림자 모드 연결 (app.py, 아직 하지 않음)
1. import: `from . import doc_ai` / `import doc_ai` (doc_registry 옆).
2. `ingest_screenshot` PDF 분기, `doc = await asyncio.to_thread(doc_registry.classify, raw)` **바로 다음**:
   ```python
   if doc_ai.shadow_enabled():  # Gemini page classifier next to the rules; logged only, never acted on
       background.add_task(doc_ai.shadow, raw, doc, user["id"], f"ingest:{image.filename or ''}")  # sync: threadpool
   ```
   응답을 늦추지 않는다(BackgroundTasks 는 응답 뒤 실행). 사용자 정보는 gemini_usage ContextVar 를 따라가므로
   `pick3_gemini_usage` 에도 feature=`doc_ai` 로 같이 기록된다.
3. 암호 문서를 연 뒤(`doc_open` → `_guess_kind`)에도 같은 줄을 넣는다(doc_ref=`doc:{doc_id}`). 이때 raw 는 열린 사본.
4. 켜기: Render 환경 변수 `PICK3_DOC_AI_SHADOW=1` (기본 꺼짐). 끄면 호출·비용 0.
5. 사용자가 문서함에서 종류를 고치면(`doc_classify`) 같은 sha256 행에 `user_type` 을 채운다(정답 표본, 3단계 재료):
   `PATCH /rest/v1/pick3_doc_class_log?sha256=eq.<hash>&user_id=eq.<id>` `{"user_type": kind}`.

### 기록 표 (마이그레이션 012 제안)
```sql
-- Pick3 migration 012: shadow log of the Gemini page classifier next to the rule registry. Safe to re-run.
create table if not exists public.pick3_doc_class_log (
    id bigint generated by default as identity primary key,
    created_at timestamptz not null default now(),
    user_id bigint,
    doc_ref text,                 -- ingest:<filename> | doc:<id>
    sha256 text,                  -- same file shared twice = same hash (dedupe, link user corrections)
    pages int not null default 0,
    rule_type text not null default '', rule_box text not null default '',
    rule_confidence text not null default '', rule_via text not null default '',
    rule_sections jsonb not null default '[]',
    ai_status text not null default '', ai_type text not null default '', ai_box text not null default '',
    ai_confidence real not null default 0, ai_segments jsonb not null default '[]',
    ai_needs_image jsonb not null default '[]',
    agreement text not null default '',   -- agree | disagree | ai_only | rule_only | both_none | ai_failed
    flags jsonb not null default '{}',    -- same_type, same_box, same_sections, same_pages
    user_type text,                       -- what the user chose later (ground truth), if any
    model text not null default '', prompt_tokens int not null default 0, output_tokens int not null default 0,
    usd real
);
create index if not exists pick3_doc_class_log_user on public.pick3_doc_class_log (user_id, created_at desc);
create index if not exists pick3_doc_class_log_sha on public.pick3_doc_class_log (sha256);
create index if not exists pick3_doc_class_log_agree on public.pick3_doc_class_log (ai_type, agreement);
alter table public.pick3_doc_class_log enable row level security;  -- server key only, like the other tables
```

## 승격 규칙 (AI 결과를 실제로 쓰는 조건)
종류별로 따로 판단한다(전체 평균이 아니라).
1. **규칙이 모르는 문서만 먼저**: 규칙 결과 없음/낮음 + AI 확신도 ≥ 0.9 인 종류는, 그 종류의 그림자 기록 중
   정답(`user_type`)이 있는 표본이 **20건 이상, 정확도 95% 이상**이면 "추정(suggested)"으로 문서함에 보여 준다(자동 저장 아님).
2. **자동 처리**: 같은 종류에서 규칙과 AI 가 **연속 50건 일치**하고 사용자 수정이 그 종류에 0~1건일 때만, 규칙이 없는 변형(제목이 다른 양식)에 AI 결과로 자동 저장을 허용한다.
3. **구간(나의건강기록)**: `same_pages` 가 30건 이상 모두 참일 때 AI 구간을 규칙 구간의 대체(규칙이 실패할 때)로 쓴다.
4. **되돌리기**: 승격 뒤 사용자 수정 비율이 5%를 넘으면 그 종류를 다시 그림자로 내린다.
5. 규칙이 높음(제목)인데 AI 가 다르면 규칙이 이긴다 — 기록만 하고 주간 점검에서 본다.

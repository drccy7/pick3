# Pick3 · 10초 맛집 결정기 (No-List Mobile Web)

목록 20개를 스크롤하는 대신, **메뉴 입력 + 원탭 상황 선택**만으로 지금 바로 갈 **1순위 1곳 + 대안 2곳**만 골라주는 초간단 모바일 웹 MVP입니다.

## 주요 기능
- **원탭 상황 필터**: `[혼자 / 점심]`, `[둘이서 / 데이트]`, `[여럿이 / 회식]`
- **No-List 큐레이션**: 최대 3곳(1순위 + 대안 2곳)만 추천 사유·가격 노트·태그와 함께 제시
- **원탭 지도 연결**: 네이버 지도 / 카카오맵 검색 바로가기 및 카톡 공유용 요약 텍스트 복사
- **선택적 실시간 연동**: `KAKAO_REST_API_KEY` 환경변수 설정 시 카카오 로컬 API 연동 (미설정/오류 시 안전 폴백)

## 빠른 실행

```bash
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8088
```

브라우저에서 `http://127.0.0.1:8088` 접속 (Windows는 `run_pick3.bat` 실행).

## 인스타 맛집 저장 (iPhone 뒷면 탭 · 공유 시트)

인스타 게시물을 보다가 **iPhone 뒷면을 두 번 탭**하거나, 스크린샷을 **공유 → Pick3 저장**하면 화면을 분석해 맛집을 저장합니다. 저장한 곳은 앱의 **📌 내 저장**에서 가까운 순·동네 순으로 3곳 추천됩니다.

```
뒷면 탭(스크린샷) 또는 공유 시트(이미지) → 단축어: JPEG → POST /api/ingest/screenshot
 → Gemini(PICK3_GEMINI_MODEL)가 상호·동네·메뉴 추출
 → 카카오 로컬로 같은 가게(음식점 FD6·카페 CE7)인지 확인, 주소·좌표 확정
 → Supabase에 사용자별로 저장(같은 사람의 상호+주소 중복 무시) → 결과 문구 표시
```

### 사용자와 토큰

저장 목록은 사람마다 따로입니다. 각자 받은 **개인 토큰**으로 구분합니다(서버에는 토큰의 SHA-256 해시만 저장).

1. 처음 한 번: Supabase SQL Editor에서 `docs/SUPABASE_MIGRATION_002_users.sql` 실행 (`SUPABASE_SETUP.sql` 다음)
2. 사용자 추가: `python scripts/pick3_users.py add 홍길동` → 토큰과 **개인 시작 링크**(`start.html#t=<토큰>`)가 **한 번만** 표시됨. 링크만 전달하면 됨
   - 시작 페이지: ① 토큰 복사 + 단축어 설치 ② 내 저장 열기(토큰 자동 저장). `#` 뒤 토큰은 서버로 전송되지 않음
3. 그 밖의 관리: `list`, `rotate <id>`(토큰 분실·유출 시 재발급), `disable <id>`, `enable <id>`

받은 사람은 토큰을 ① 단축어 헤더에 넣고 ② 웹앱 **📌 내 저장**을 처음 누를 때 붙여넣습니다(이 기기에만 보관). `https://…/?token=<토큰>` 링크로 열어도 저장됩니다.

#### 이름 + PIN 로그인 (웹 화면)

브라우저마다 개인 링크를 다시 열지 않아도 되게, 웹 화면(홈·의료비·처방·맛집 목록)은 **이름 + PIN 6자리**로도 들어올 수 있습니다. 단축어는 여전히 개인 토큰을 씁니다.

- 처음 한 번: Supabase SQL Editor에서 `docs/SUPABASE_MIGRATION_005_pin.sql` 실행
- PIN은 **사용자가 직접** 만듭니다: 개인 링크로 들어간 기기의 홈 → **PIN 만들기**. 관리자는 PIN을 볼 수 없습니다(소금 친 PBKDF2 해시만 저장)
- 다른 브라우저: 홈의 **이름과 PIN으로 들어가기** → 그 브라우저용 세션 토큰(`p3s_…`)이 발급되어 개인 토큰처럼 쓰임. 홈 아래 **이 기기에서 로그아웃**으로 끝냄
- 막기: 같은 사람 PIN 5번 틀리면 15분 잠금, IP당 시간당 20번 실패 제한. 같은 숫자·연속 숫자(111111, 123456) 금지
- 관리: `reset-pin <id>`(PIN 잊음·잠김 해제), `logout-all <id>`(웹 로그인 모두 끝내기). `rotate <id>`는 웹 로그인도 모두 끝냄. `list`에 PIN 유무 표시

#### 사람별 전용 단축어 링크 (토큰 붙여넣기 없이 설치)

가져오기 질문 링크 대신, 그 사람 토큰을 미리 넣은 단축어를 따로 공유하면 받는 사람은 **단축어 추가**만 누르면 됩니다.

1. 단축어 앱에서 `의료비 저장`(또는 `Pick3 저장`)을 길게 눌러 **복제**
2. 복제본 맨 위 **텍스트** 동작에 그 사람 토큰을 붙여넣음
3. ⓘ → **설정** → 가져오기 질문에서 그 텍스트 질문을 **삭제** (안 지우면 받는 사람에게 다시 물음)
4. 복제본 이름을 원래 이름(`의료비 저장`)으로 바꾼 뒤 **공유 → iCloud 링크 복사** → 그 사람에게 **1:1로** 전달
5. 링크를 만든 뒤 복제본은 지움(내 폰에 남의 토큰 단축어가 남지 않게)

주의: 이 링크는 **열쇠**입니다. 단톡방이나 공개된 곳에 올리지 말고, 새면 `rotate <id>`로 토큰을 바꿉니다. 단축어를 고칠 때마다 사람별 링크도 다시 만들어야 합니다.

하루 한도: 사람당 `PICK3_DAILY_LIMIT_PER_USER`(기본 30건, 사용자별 `daily_limit`이 있으면 그 값), 전체 `PICK3_DAILY_LIMIT_TOTAL`(기본 300건). 넘으면 Gemini를 부르지 않고 "한도" 문구를 돌려줍니다.

### 서버 환경변수 (Render)

| 키 | 설명 |
|---|---|
| `SUPABASE_URL`, `SUPABASE_KEY` | 저장소. 키는 **secret 키(`sb_secret_…`)**. 테이블은 `docs/SUPABASE_SETUP.sql` 실행 |
| `GEMINI_API_KEY` | 화면 분석 |
| `PICK3_GEMINI_MODEL` | 선택. 기본 `gemini-3.5-flash-lite`. 인식이 약하면 `gemini-3.8-flash` |
| `KAKAO_REST_API_KEY` | 가게 확인·좌표 |
| `PICK3_DAILY_LIMIT_PER_USER`, `PICK3_DAILY_LIMIT_TOTAL` | 선택. 하루 분석 한도 (기본 30 / 300) |
| `PICK3_INGEST_TOKEN` | Supabase 없이 로컬에서만 쓰는 공용 토큰. 운영(Supabase)에서는 쓰지 않음 |

> Render 서비스는 Auto-Deploy가 꺼져 있습니다. push 후 **Manual Deploy → Deploy latest commit**. 환경변수만 바꿀 때는 "Save only" 후 배포.
> 확인: `GET /api/health` → `storage_ok`, `gemini_key_configured`가 `true`, `auth_mode`가 `per_user`.

### 단축어 설치 (링크)

[Pick3 저장 단축어](https://www.icloud.com/shortcuts/6a903267abf944b99158e1214fffcf1c) → **단축어 추가**만. 링크는 모두에게 같고 토큰이 없습니다.
계정 연결은 개인 시작 페이지의 **[단축어에 내 계정 연결]**: `shortcuts://run-shortcut?name=…&input=text&text=<토큰>`으로 단축어를 실행하면, 단축어가 토큰을 `Shortcuts/pick3_token.txt`에 저장하고 이후 매번 그 파일에서 읽습니다. 두 단축어가 같은 파일을 쓰므로 한 번만 연결하면 됩니다. 토큰을 바꾸면(`rotate`) 새 시작 링크에서 버튼만 다시 누르면 됩니다. 뒷면 탭은 아래 "뒷면 탭 연결"대로 직접 켭니다.
단축어를 고치면 iCloud 링크를 새로 만들어 여기를 바꿔야 합니다.

### 단축어 만들기 (iOS 18+ 한국어 기준)

직접 만들 때: 단축어 앱 → **＋** → 제목을 눌러 **이름 변경: `Pick3 저장`**. 맨 위에 **텍스트** 동작(내 토큰)을 두고 헤더 값에 그 변수를 넣으면, ⓘ → 설정 → 가져오기 질문으로 링크 배포가 됩니다. 아래 ⓘ → **공유 시트에서 보기** 켜기. 그러면 맨 위에 "공유 시트에서 … 받기" 블록이 생깁니다. 이어서 아래 동작을 순서대로 추가합니다.

```
공유 시트에서 이미지·파일·텍스트 받기 (입력이 없는 경우: 계속하기)
텍스트: 단축어 입력
조건문: 텍스트 이(가) p3_ (으)로 시작함 인 경우          ← 계정 연결 (시작 페이지 버튼)
    파일 저장: 텍스트 → Shortcuts, 하위 경로 pick3_token.txt, 덮어쓰기 켬, 저장 위치 묻기 끔
    콘텐츠 보기: ✅ 연결 완료
    단축어 중단
조건문 종료
파일 가져오기: Shortcuts 폴더의 pick3_token.txt (찾을 수 없을 때 오류 끔)
조건문: 파일 값을 가지고 있지 않음 인 경우
    콘텐츠 보기: 먼저 시작 페이지에서 [단축어에 내 계정 연결]을 눌러 주세요
    단축어 중단
조건문 종료
조건문: 단축어 입력 값을 가지고 있지 않음 인 경우
    스크린샷 찍기
그렇지 않은 경우
    단축어 입력 가져오기
조건문 종료
조건문 결과 을(를) JPEG (으)로 변환
URL 콘텐츠 가져오기 → 사전 값 가져오기 → 사전 값 보기
```

1. **받기 블록**: 입력 유형은 `이미지`만, 입력이 없는 경우 `계속하기` (뒷면 탭 실행이 이쪽)
2. **조건문**(검색어 "조건문", 분류 스크립팅 → 제어 흐름): 입력 `단축어 입력`, 조건 `값을 가지고 있지 않음`. **"앨범"으로 보이면 잘못된 것**: 앨범(사진 속성)을 검사하면 PDF·파일은 늘 "값 없음"이 되어 공유한 파일 대신 현재 화면을 캡처함. "앨범"을 눌러 목록 맨 위 `단축어 입력`을 고를 것
   - 첫 칸에 **스크린샷 찍기**, `그렇지 않은 경우` 칸에 **변수 가져오기 → 단축어 입력**
3. **이미지 변환** → 입력 `조건문 결과`, 형식 `JPEG`, `>` 눌러 **메타데이터 유지 끔**
4. **URL 콘텐츠 가져오기**
   - URL: `https://pick3-api.onrender.com/api/ingest/screenshot`
   - `>` 펼치기 → **메소드 `POST`** (GET이면 "Method Not Allowed")
   - **헤더** → 새로운 헤더 추가: `X-Pick3-Token` = 파란 변수 **파일** (pick3_token.txt 내용)
   - **본문 요청** → `형식`(양식) → **새로운 필드 추가 → 파일** → 키 `image`, 값은 파란 변수 **변환된 이미지**
     (키 칸에 변수를 넣지 않도록 주의. 헤더가 아니라 본문 필드입니다)
5. **사전 값 가져오기** → `URL 콘텐츠`에서 `message`에 대한 값
6. **콘텐츠 보기** → 파란 **사전 값** (예전 이름 "결과 보기")
   - "시스템 알림 보기"는 단축어 앱에 알림 권한이 없으면 아무것도 안 뜹니다. 콘텐츠 보기를 쓰세요.

편집 화면에는 "완료" 버튼이 없습니다(자동 저장, 왼쪽 위 ‹ 로 나가기).

**뒷면 탭 연결**: 설정 → 손쉬운 사용 → 터치 → 뒷면 탭 → 이중 탭 → `Pick3 저장`.

**공유로 저장**: 캡처 → 왼쪽 아래 썸네일 → 공유 → `Pick3 저장` (사진 앱의 예전 스크린샷도 가능). 목록에 없으면 공유 시트 맨 아래 **작업 편집…**에서 즐겨찾기 추가.

### 사용 요령과 결과 문구

- 인스타에서 **캡션 "…더 보기"를 펼친 뒤** 탭하면 정확합니다(📍상호·주소가 보이게).
- 단축어 편집 화면에서 ▶로 실행하면 단축어 앱 화면이 찍혀 "찾지 못했습니다"가 정상입니다.
- 처음엔 "연결 허용"이 뜰 수 있음 → 항상 허용. 서버가 잠들어 있으면 첫 응답 30~50초.

| 문구 | 의미 |
|---|---|
| ✅ 저장 완료: 상호 (동네) | 저장됨 |
| 이미 저장된 곳입니다 | 내 목록에 같은 상호·주소가 이미 있음 |
| 오늘 저장 한도(…건)를 넘었습니다 | 하루 한도 초과. 다음 날(한국 시간) 초기화 |
| ⚠ …위치 확인 필요 | 저장했지만 카카오에서 같은 가게를 확정 못 함(좌표 없음). 지점·동네가 보이는 화면으로 다시 |
| 음식점 이름을 찾지 못했습니다 | 화면에 상호가 없음 |
| ❌ 저장 실패 / 화면 분석 실패 | 서버·외부 API 문제. 잠시 후 재시도 |
| Invalid or missing X-Pick3-Token | 헤더 이름·토큰 오타, 등록 안 된 토큰, 사용 중지된 사용자 |

## 첫 화면 (서비스 선택)

`index.html`은 서비스를 고르는 첫 화면이고, 맛집 앱은 `pick3.html`, 의료비는 `medical.html`입니다. 새 서비스는 `index.html`의 `SERVICES` 배열에 한 줄(아이콘·이름·설명·페이지)을 더하고 페이지 파일을 추가하면 됩니다(Render에서도 열려면 `app.py`의 페이지 라우트에 경로 추가). 개인 토큰은 기기의 `localStorage`(`pick3_token`)에 한 번 저장되어 모든 서비스가 같이 씁니다.

## 단축어 하나로 모든 서비스 (자동 판별)

`POST /api/ingest/screenshot`(= "Pick3 저장" 단축어)은 먼저 Gemini로 화면 종류를 판별(`screen_router.py`: 맛집 / 의료비 / 기타)한 뒤 그 서비스의 추출기로 보냅니다. 그래서 **Pick3 저장 하나만 설치하면** 의료비 결제 내역 캡처도 의료비 기록에 저장되고, 토큰을 두 번 넣을 필요가 없습니다. 결과 첫 줄에 `🍽️ 맛집` 또는 `🧾 의료비 기록`이 표시됩니다. 판별 호출이 1회 늘어(약 2초) 끄려면 `PICK3_AUTO_ROUTE=0`. PDF는 이미지 전용인 Pick3 저장으로는 못 보내므로 "의료비 저장" 단축어를 씁니다.

새 서비스를 붙일 때: 판별 종류를 `screen_router.py`에 추가하고, `app.py`의 라우팅 분기에서 그 서비스의 저장 함수를 부르면 됩니다.

## 처방·조제 기록 (💊)

심평원 '내가 먹는 약' **처방조제정보 PDF**를 "의료비 저장" 단축어로 보내면 첫 쪽 제목을 보고 처방 기록으로 저장합니다(진료비 PDF는 의료비로). 보기: `prescriptions.html`(고객·연도·처방/조제 필터, 약품·성분 검색, 열 정렬, CSV, 이름 일괄 변경, 고객 단위 삭제).

- 추출: 글자층이 있는 PDF는 **pdfplumber**(MIT)로 표를 그대로 읽음 — 무료·결정적, 순번 1..N 연속 검사로 누락 알림. 표가 없는 PDF(스캔)와 캡처 화면은 Gemini. Pick3 저장의 자동 판별에도 `prescription` 종류가 있음
- 저장: `pick3_prescriptions`(`docs/SUPABASE_MIGRATION_004_prescriptions.sql`), 같은 고객·날짜·기관·약품은 한 번만
- 이름: 입력한 이름(`patient` 필드) > 화면의 이름 > **파일 이름 앞의 한글 이름**(예: `홍길동 약처방.pdf`) > 최근 이름. 파일 이름·최근 이름을 쓴 경우 결과 문구에 표시
- API: `GET /api/prescriptions`, `POST /api/prescriptions/patient`, `DELETE /api/prescriptions?patient=`, `DELETE /api/prescriptions/{id}`

## 의료비 기록 (보험금 청구용)

병원·약국 결제 내역 화면(스크린샷) 또는 PDF를 공유하면 **환자 이름 + 기관·구분·금액·날짜**를 표로 저장합니다. 보기: `medical.html` (환자·연도·구분 필터, 합계, 엑셀용 CSV, 행 삭제).

- 처음 한 번: Supabase에서 `docs/SUPABASE_MIGRATION_003_medical.sql` 실행
- API: `POST /api/ingest/medical`(multipart `image`, 이미지·PDF), `GET /api/medical?patient=&year=`, `DELETE /api/medical/{id}` — 모두 `X-Pick3-Token`
- 중복: 같은 환자·기관·날짜·금액은 한 번만 저장(스크롤하며 여러 장 캡처해도 안전). 잘려서 안 보이는 행은 추측하지 않고 뺌
- 이름 탭이 여러 개인 화면은 **선택된 탭의 이름**을 환자로 씀
- **고객 이름 지정(보험설계사용)**: 본문 필드 `patient`(텍스트)를 함께 보내면 화면의 이름 대신 그 이름으로 저장(설계사 본인 토큰, 고객 토큰 불필요). 화면 이름과 다르면 결과 문구에 경고. 고객 기록 전체 삭제: `DELETE /api/medical?patient=이름` 또는 의료비 화면에서 고객을 고른 뒤 [전체 삭제](이름 재입력 확인)
- 이름이 없는 화면(영수증 등)은 **가장 최근에 저장한 환자**로 저장하고 결과 문구에 알림. 틀리면 의료비 화면에서 행을 눌러 환자를 바꾸며, 같은 캡처로 저장된 행을 한 번에 바꿀 수 있음(`POST /api/medical/patient`)

**단축어 "의료비 저장"**: [설치 링크](https://www.icloud.com/shortcuts/751eda5649704a42a0447a86f8fced72) (토큰은 가져오기 질문, 시작 페이지에도 버튼 있음). 직접 만들 때는 Pick3 저장을 복제해서 수정:
1. Pick3 저장 길게 누르기 → 복제 → 이름 `의료비 저장`
2. 맨 위 받기 블록 입력 유형: `이미지`와 `PDF` 켜기
3. **이미지 변환** 블록 삭제 (PDF는 변환 불가, 서버가 PNG·JPEG·HEIC·PDF를 직접 받음)
4. URL 콘텐츠 가져오기: URL을 `https://pick3-api.onrender.com/api/ingest/medical`로, 본문 필드 `image` 값을 `조건문 결과`로
